Scrollspy

Bootstrap's data-bs-spy API — scrolling the content updates the active navigation item. The active state is Bootstrap's own .active class on nav links, carried by the existing IndigoKit pill treatment. No custom scroll tracking.

Overview

IndigoKit is a reusable Modern + Enterprise UI framework on top of Bootstrap 5.3. This documentation page demonstrates the scrollspy pattern: a sticky navigation column that highlights the section currently in view.

The active item is marked by Bootstrap's scrollspy toggling .active on the matching nav link — the same class the tabs and pills systems use, so the indigo pill treatment applies automatically.

Configuration

Configuration lives in src/scss/base/_tokens.scss — colors, spacing, radius, shadows, and motion map onto Bootstrap's variables before the framework is imported.

Component refinements sit in src/scss/components/, each file holding only the rules Bootstrap genuinely needs. The build is a single Sass CLI pass with no bundler.

Consumer integration is plain Bootstrap: import the compiled CSS and optional dist/js/indigokit.js, then write standard Bootstrap markup.

Security

Authentication and authorization follow your existing application architecture — IndigoKit is presentation only and never intercepts credentials or session state.

Form validation is server-render compatible: the markup works with ASP.NET MVC, Razor, and standard HTML forms, and validation feedback uses the dark emphasis colors (measured ≥8:1).

Never store secrets in the repository; inject them at deploy time via environment variables or your platform's secret manager.

Notifications

Toasts are transient event notifications — success, info, warning, and error variants with deliberate live-region semantics (role="status" for non-urgent, role="alert" for errors).

Alerts remain the pattern for persistent page-level information. The two complement each other and never replace one another.

Advanced

Advanced options include the application shell (navbar + collapsible sidebar + mobile drawer), the Bootstrap-first component library, and the Phase 6 data-display set: tables, progress, loading, toasts, list groups, and empty states.

The scrollspy pattern itself composes from existing utilities — a sticky nav column, semantic sections, and Bootstrap's own spy. No navigation framework is required.

Nested navigation & mobile

One level of nested nav (Configuration → child links) demonstrates the parent/child active handling. On mobile the nav lives in an offcanvas drawer — the same links, the same spy target, so the active state works from the drawer too.

Accessibility notes

  • Navigation is a real <nav> with an accessible name (aria-label), and links point to real section IDs — the same markup works with or without scrollspy.
  • Bootstrap toggles .active on the nav link of the section in view; the indigo pill + strong text carries the state (never color alone). The data-bs-smooth-scroll option animates anchor jumps and respects reduced motion.
  • Headings follow the document structure (h2 for sections, h3 for nested ones); sections are semantic <section> elements.
  • Mobile: the nav moves into an offcanvas drawer (the existing offcanvas pattern) — the same spy target, so the active state tracks correctly from the drawer.
  • No custom scroll listeners, analytics, or reading-progress tracking — this is Bootstrap's own scrollspy.
