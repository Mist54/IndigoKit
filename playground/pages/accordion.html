Accordion & collapse

Bootstrap's .accordion / .collapse with IndigoKit styling — hairline borders, 6px radius, indigo emphasis on the open header, the global indigo focus ring, and Bootstrap's own collapse transition (reduced-motion aware). Best for grouped, progressive information — not for content users need to compare side by side.

Basic accordion

Standard single-open behavior — opening one item closes the others. Bootstrap's collapse JS drives everything; no custom state.

Colors, spacing, radius, shadows, and motion tokens live in src/scss/base/_tokens.scss and map onto Bootstrap's variables. Every component compiles against them.

Components extend Bootstrap's public API — refinements live in src/scss/components/, and JavaScript stays with Bootstrap (or minimal guarded init in indigokit.js).

Every component has a reference page in playground/pages/, linked from the index. No inline styles, no embedded framework CSS — the playground consumes the compiled output.

Independent collapse

Without a data-bs-parent, each panel opens and closes on its own — useful for filters and settings with unrelated sections.

Settings & forms

Accordion as a settings surface — the form controls keep their labels, focus, and validation; the collapse transition never moves focus unexpectedly (it closes on the same button that opened it).

Long content

Every IndigoKit component is checked in the browser, not assumed: computed styles for contrast, the global indigo :focus-visible ring on every control, live-region behavior for toasts and alerts, and keyboard-only passes over tabs, modals, dropdowns, and accordions. Validation text uses the dark emphasis colors (measured ≥8:1), icons are decorative unless they carry essential meaning, and motion respects prefers-reduced-motion.

Known limitations are documented honestly in the playground pages — for example, the preview environment cannot animate transitions, so motion is verified in the compiled CSS rather than live.

Accessibility notes

  • Each panel header is a real <button> inside a semantic heading — aria-expanded, aria-controls, and the region IDs are managed by Bootstrap's collapse JS; no manual duplication.
  • Keyboard: Tab/Shift+Tab move through the header buttons (visible indigo focus ring), Enter/Space toggle them — native button behavior, no custom navigation.
  • The chevron flips on open and the open header gains indigo emphasis (color + weight context), so the active item is never color-only.
  • Bootstrap's collapse transition is reduced-motion aware; no custom animation is added.
  • Use accordions for progressive information (FAQ, settings, advanced options) — not for content users must compare simultaneously (use cards or tables there).
  • Forms inside accordion panels keep their labels, focus, and validation; collapsing happens on the same control that opened the panel, so focus never jumps.
