Themes

IndigoKit's theme architecture. The mechanism is Bootstrap's native data-bs-theme attribute on <html> — no IndigoKit theme classes, no runtime engine. This page flips the whole document so every surface inconsistency is visible. Use the switcher above; the choice persists across playground pages (localStorage key indigokit-theme).

How it works

Build-time dark variables (base/_themes.scss, before the Bootstrap import) drive Bootstrap's own [data-bs-theme="dark"] root block — body, text, surfaces, borders, emphasis tints, validation colors. Runtime dark rules (end of base/_base.scss) cover the handful of things Bootstrap cannot express at build time: baked-SVG validation icons, the focus ring, backdrop, shell hover surfaces. Light mode output is unchanged except focus rings now emit var(--bs-focus-ring-color) (same value).

Surface hierarchy

Three dark neutrals in the slate family (body → raised → hover), demonstrated with Bootstrap's bg-body / bg-body-secondary / bg-body-tertiary utilities. Overlays (modal/offcanvas/dropdown/popover/toast) sit on the raised surface; borders use slate-600.

Typography

Headings, lead, body and muted text all flow from --bs-body-color / --bs-secondary-color; links stay indigo (Bootstrap lightens the link tint in dark); selection, <mark>, blockquote and code flip via token-driven tints.

Buttons

Semantic colors are constant across themes (indigo stays indigo) — only neutrals, surfaces and emphasis tints flip. Contrast measured in dark: white on indigo 6.3:1; dark ink on emerald/amber/red/cyan 5.0–8.8:1.

Accessibility notes

  • Text contrast (measured): primary slate-200 on slate-900 ≈ 14.5:1; secondary ≈ 8.5:1; tertiary ≈ 4.2:1 (used for muted/large text — above the 3:1 non-text bar).
  • Validation: feedback text/borders/labels flip to the light-emphasis tints; the feedback icons are re-emitted for dark (baked SVG fix); tooltip text flips to dark ink on the light tint (≈8:1).
  • Borders: slate-600 on body ≈ 2.4:1 — visible but soft (Bootstrap's own dark borders measure ≈ 2.3:1).
  • Backdrop: black at 50% in dark (the light slate scrim would vanish against the dark body).
  • Semantics: theming changes no markup, roles or behavior — every control keeps its accessible name, label, focus and keyboard model from the light theme.
  • Theme modes (Task 047): Light / Dark force a theme; System follows prefers-color-scheme via matchMedia() and reacts to OS changes. The choice persists in localStorage under indigokit-theme (allowlist-validated; invalid values fall back to System; blocked storage degrades to session-only). The stored preference applies before first paint on every playground page via the shared playground/theme.js — no flash of the wrong theme. The switcher is a native .form-select with a visible label, keyboard access and announced value. IndigoKit itself still ships no theme JavaScript.
