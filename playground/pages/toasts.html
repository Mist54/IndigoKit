Alerts vs toasts

The distinction: an alert is persistent page-level information that stays until dismissed or the page changes; a toast is a transient notification about an event. Neither replaces the other.

Persistent warning: your plan renews in 3 days. This stays on the page — an alert, not a toast.

Progress toast

A toast with a live progress bar — useful for uploads, exports, or long-running operations. The progress is updated via inline width and aria-valuenow.

Accessibility notes

  • role="status" (polite live region) for non-urgent information — announcements queue behind the user's current task; role="alert" (assertive) only for urgent/error messages. Applied deliberately, not blanket-applied.
  • aria-atomic="true" makes the region announce the whole toast as one unit — the header + body are announced together, avoiding duplicate or fragmented announcements.
  • Icons are decorative (aria-hidden); the text carries the meaning. There are no icon-only toasts.
  • The dismiss button is Bootstrap's real .btn-close — keyboard-focusable, named "Close", 32px+ hit area.
  • Auto-dismiss: 5s for success/info; errors persist until dismissed (urgent information must not vanish). data-bs-autohide="false" on the error toast.
  • Live regions announce only when a toast appears — the static examples on this page are already shown, so they announce on load in the order shown; in a real app, toasts are created/triggered by events.
