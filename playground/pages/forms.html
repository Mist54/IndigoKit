Accessibility examples

  • Every control has an associated <label> via for/id — placeholders are never the label.
  • Help text and error messages are linked with aria-describedby; native required carries requiredness (no redundant ARIA).
  • Required fields show visible "(required)" text, not a lone red asterisk.
  • Validation feedback uses the dark emphasis colors (≈8.5:1 / ≈8.8:1 contrast) and the message text explains the problem — never color alone.
  • Choice controls use native .form-check semantics: for/id labels, same-name radio groups, fieldset/legend for related choices, native required, and the checked mark is a white glyph on solid indigo (≈6.3:1) — no ARIA beyond what HTML provides.
  • The indeterminate checkbox uses the native DOM property (styled by Bootstrap's :indeterminate) — no IndigoKit class or API.
  • Switches are native checkboxes with Bootstrap's .form-switch presentation (role="switch" for the toggle semantics); state is conveyed by knob position and color, never color alone, and the off knob is slate (≈4.8:1).
  • Range controls are native .form-range inputs with associated labels — min/max/value are exposed to assistive technology automatically.
  • Input-group addons are contextual, not labels — every control keeps its own <label>, and aria-describedby is used only where an addon adds genuinely useful supplementary information. Addon icons are decorative (aria-hidden="true").
  • Disabled controls are muted and unreachable; readonly controls keep their editable look (still focusable/selectable).
  • Focus uses the global indigo ring — keyboard users can always see where they are.
  • Validation: errors use aria-invalid="true" where the native :invalid semantics aren't active (e.g. static/novalidate forms), and aria-describedby ties each control to its help/error text. Messages are specific and actionable, never color-only, and the invalid icon is a dark-red glyph matching the border and message.
  • Validation timing: errors are announced when they appear — the summary uses role="alert", but live regions are not scattered across every field (that would double-announce). No aggressive keystroke-by-keystroke validation is demonstrated.
  • Server compatibility: every example is plain server-renderable HTML — no client-side validation engine; ASP.NET MVC/Razor style markup works unchanged.
