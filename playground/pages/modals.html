Modals

Bootstrap's modal API with IndigoKit refinement — all classes are standard Bootstrap (.modal, .modal-dialog, .modal-content, .modal-header/-body/-footer, .modal-sm/-lg/-xl, .btn-close). Behavior comes from Bootstrap's own Modal JavaScript.

Accessibility note: every modal has an accessible name (aria-labelledby); focus moves into the modal when it opens, is contained while it is open, and returns to the trigger when it closes. Background content is inert while a modal is open (scroll locked, focus trapped).

Destructive confirmation

Confirmation flows use a static backdrop (data-bs-backdrop="static") + data-bs-keyboard="false" so the dialog cannot be dismissed accidentally. The text states exactly what will happen — the red button is reinforcement, not the only cue.

Delete project?

This permanently deletes the project and all of its data, including reports and audit history. This action cannot be undone.

Static backdrop

With data-bs-backdrop="static", clicking the backdrop does not close the modal — only the close button, footer actions or Esc (when keyboard is enabled) close it.

Unsaved changes

Click the backdrop — nothing happens. Choose an action instead.

Keyboard and focus behavior

Esc closes a modal (unless data-bs-keyboard="false"); Tab/Shift+Tab move through modal controls and wrap at the edges (focus never reaches the page behind); opening moves focus into the modal; closing returns focus to the trigger button. Try it on any modal above.

Nested modals

Nested modals are not supported in IndigoKit — they complicate focus management and stacking. If a workflow seems to need a modal inside a modal, prefer a single dialog, an in-modal view switch, or a dedicated page.
